# Dataset sources and what to obtain

Last checked: 29 September 2026. These are publisher-maintained pages or links supplied by the dataset authors. Public archive URLs marked as probed below returned only a small byte range; I did **not** download any complete dataset or verify an authenticated download end to end. A successful probe is not proof of a completed full transfer. ImageNet and Stanford access can require an account, acceptance of terms, or approval. Respect the publishers' conditions even where an archive endpoint responds without a login. Large archive links may redirect to short-lived signed URLs, so use the stable landing page if a direct archive link stops working.

## Which dataset plan does this document cover?

The [project implementation guide](implementation_guide.md) calls for four domains: ImageNet-1K, CUB-200-2011, PASCAL VOC 2012 segmentation, and a CheXpert subset for five findings. To evaluate *localization* (whether an explanation highlights the right part of an image), images and class labels alone are insufficient. The complete guide-aligned acquisition set is:

1. **ImageNet-1K** images/labels **plus ImageNet-S-50** splits and pixel masks for localization.
2. **CUB-200-2011** images/class/part/bounding-box annotations **plus the separate segmentation archive**.
3. **VOC2012 train/validation archive**, using only its segmentation split and masks; optionally add SBD if reproducing the larger `trainaug` split.
4. **Original CheXpert v1.0** images/labels, filtered to the five findings, **plus CheXlocalize** radiologist localization annotations.

The present repository instead configures **NIH ChestX-ray14** as its fourth dataset in [`configs/nih_chestxray.yaml`](../configs/nih_chestxray.yaml) and [`scripts/verify_datasets.py`](../scripts/verify_datasets.py). NIH is documented separately below for running the *current* project. Downloading CheXpert/CheXlocalize does not make the current NIH pipeline use them; code/configuration changes are still needed. Likewise, acquiring data alone does not fix the current dataset loaders or validate the localization results.

## 1. ImageNet-1K + ImageNet-S-50

**What it is and why it is needed.** ImageNet-1K (ILSVRC 2012) supplies the broad 1,000-class natural-image classification data used for the ImageNet experiment and as the image source for ImageNet-S-50. ImageNet-S-50 selects 50 of those classes and supplies segmentation annotations, allowing an attribution map to be compared against the actual object pixels. The base ImageNet archive by itself does **not** provide the ImageNet-S masks.

For reproducible local localization scores, use the ImageNet-S-50 **validation images and `validation-segmentation` masks**. Its test images do not come with public test masks; test evaluation uses the authors' online server. The authors list 64,431 train, 752 validation and 1,682 test images for S-50. Decode mask IDs as `R + 256*G`; `1000` is ignore and `0` is “other.” Keep the ImageNet synset-to-class mapping rather than assuming folder order matches mask IDs.

## 2. CUB-200-2011 + segmentation masks

**What it is and why it is needed.** CUB contains 11,788 images of 200 bird species. Fine-grained explanations should highlight diagnostic bird regions, not just background. The main archive gives class labels, official train/test split, bird bounding boxes and **15 part-location points**. Points support a part-hit/proximity test; they are not area masks. The separate segmentation archive gives bird silhouettes for pixel-overlap metrics such as IoU.

| Link | What it provides | Project use |
| --- | --- | --- |
| [Caltech CUB dataset overview](https://www.vision.caltech.edu/datasets/cub_200_2011/) | Publisher description and links to both required records. | Check usage restrictions and provenance. |
| [CUB images and annotations record](https://data.caltech.edu/records/65de6-vp158) ([`CUB_200_2011.tgz` download](https://data.caltech.edu/records/65de6-vp158/files/CUB_200_2011.tgz?download=1)) | All images, species labels, split files, bounding boxes, attributes and part locations. Published MD5: `97eceeb196236b17998738112f37df78`. | Classification/fine-tuning and box/part localization. |
| [CUB segmentations record](https://data.caltech.edu/records/w9d68-gec53) ([`segmentations.tgz` download](https://data.caltech.edu/records/w9d68-gec53/files/segmentations.tgz?download=1)) | Separate foreground masks for the bird images. Published MD5: `4d47ba1228eae64f2fa547c47bc65255`. | Pixel-level localization comparisons; required by this repository's dataset verifier. |

After extraction, align masks by image-relative path under `CUB_200_2011/segmentations/`. Preserve the provided image IDs and split files. This repository also creates a validation split from the CUB training portion; it should not use the official test images for tuning.

## 3. PASCAL VOC 2012 segmentation subset

**What it is and why it is needed.** VOC2012 has 20 object classes and scenes that may contain multiple classes. Its semantic masks give an object-level reference for comparing explanations against the target class. “Segmentation subset” means **select the images listed in `ImageSets/Segmentation/train.txt` and `val.txt` from the full VOC2012 train/validation archive**; it is not a separate official download.

| Link | What it provides | Project use |
| --- | --- | --- |
| [VOC2012 official page](https://www.robots.ox.ac.uk/~vgg/projects/pascal/VOC/voc2012/) | Publisher description, terms, development-kit links and split definitions. | Authoritative source and protocol. |
| [VOC2012 training/validation archive](https://www.robots.ox.ac.uk/~vgg/projects/pascal/VOC/voc2012/VOCtrainval_11-May-2012.tar) | `VOCdevkit/VOC2012` with JPEG images, `SegmentationClass` masks, image-set lists, object annotations and other tasks. | **Required** images and pixel masks for the official segmentation train/validation split (1,464 train and 1,449 val images). |
| [Semantic Boundaries Dataset (SBD) archive](https://www2.eecs.berkeley.edu/Research/Projects/CS/vision/grouping/semantic_contours/benchmark.tgz) ([Berkeley directory](https://www2.eecs.berkeley.edu/Research/Projects/CS/vision/grouping/semantic_contours/)) | Extra VOC-compatible segmentation annotations from a different dataset. | **Optional** only if implementing an augmented `trainaug` protocol such as the 10,582-image training split; not needed for the official VOC2012 segmentation split. |

Use the class-indexed `SegmentationClass` masks for class-specific overlap; `SegmentationObject` answers a different, instance-level question. VOC2012 public test ground-truth masks are not released, so local localization evaluation should use validation. The repository's current benchmark text mentions larger counts without a fully specified SBD integration; do not label that as the official VOC segmentation split.

## 4. Medical subset: CheXpert + CheXlocalize

**What it is and why it is needed.** The intended task is a **five-label, multi-label** chest-X-ray experiment: Atelectasis, Cardiomegaly, Consolidation, Edema and Pleural Effusion. Original CheXpert v1.0 supplies radiographs and observation labels (including uncertain labels) for model training/evaluation. It does **not** supply finding-location masks. CheXlocalize supplies radiologist-drawn pixel segmentations and representative points for a smaller, matching CheXpert evaluation subset, so localization can be measured against human annotations. Filter both resources to the same five findings; do not treat the CheXlocalize model-generated Grad-CAM maps as ground truth.

For the **validation** localization protocol, the expected pairing is CheXpert `valid/` + `valid.csv` (images and labels) with Redivis `gt_segmentations_val.json` (human localization masks). You do **not** need to download the same validation X-rays twice, but the prepared image identifiers must actually match the annotation identifiers. The authors also annotate a **test** cohort: Redivis has `gt_segmentations_test.json`, but the standard CheXpert train/validation release is not a confirmed source for those test X-rays. If the benchmark uses test localization, obtain the separately distributed test images and corresponding labels through an authorized route first. The authors' [CheXlocalize layout guide](https://github.com/rajpurkarlab/cheXlocalize/blob/master/README.md) shows both cohorts; the [CheXpert test-set labels repository](https://github.com/rajpurkarlab/cheXpert-test-set-labels) points to the older portal for test images. The Kaggle copy above may include them, but its redistribution rights have not been verified.

The five-finding task is a **selection from CheXpert**, not a separately downloadable “CheXpert 5” dataset. For full training, request the original CheXpert dataset, not merely a small sample or **CheXpert Plus** (a distinct release). Reserve CheXlocalize for localization evaluation and maintain patient-level separation from training. “Radiologist attention heatmaps” in the implementation guide should be read as **radiologist localization annotations** here; attention/Grad-CAM heatmaps are model outputs, not the human reference standard.

**If Stanford's pages keep loading:** the AIMI pages themselves are accessible, but the linked CheXpert access portal and CheXlocalize Redivis app require interactive access; I cannot tell from a public page whether your signed-in session has reached the dataset, accepted its terms, or is stuck in a browser/authentication error. Try the [current CheXlocalize Redivis link](https://stanford.redivis.com/datasets/efx9-5nspnbb4b) directly in a fresh Chrome session with blocking extensions disabled. The [authors' older instructions](https://github.com/rajpurkarlab/cheXlocalize/blob/master/download_instructions.md) are another route to ask about, but do not assume that old portal still operates. If neither works, contact [Stanford AIMI](https://aimi.stanford.edu/datasets/chexlocalize) and report the exact page, browser, and point where it hangs. There is currently **no verified stable anonymous CheXlocalize full-download URL** to hard-code into this script.

**REST API access without the browser.** The Redivis API is usable with an authorized token even while the browser app hangs. This repository's local `.env` currently names the secret `REDIVIS-DATA-API-KEY`; the downloader reads that entry as plain data (it does **not** execute the `.env` file). On a remote server, prefer providing the token through a protected `REDIVIS_API_TOKEN` environment variable; this is the [name recognized by Redivis's Python client](https://docs.redivis.com/api/client-libraries/redivis-python/getting-started) as well. The downloader sends the Bearer token to Redivis through curl's standard input, not a command-line argument. It does not print the token or signed redirect URLs. Keep `.env` private (`chmod 600 .env` on Linux), do not give a server owner unrestricted use of your personal token without agreement, and revoke/rotate it after use. The repository now ignores `.env` in Git, but an already-committed secret would still need removal and rotation.

## If running the repository unchanged: NIH ChestX-ray14 instead of CheXpert

The present verifier and configuration expect NIH ChestX-ray14, not CheXpert. The [NIH Clinical Center distribution](https://nihcc.app.box.com/v/ChestXray-NIHCC) is the source named by the [dataset authors' paper](https://arxiv.org/abs/1705.02315). Obtain **all** image archives (112,120 PNGs), `Data_Entry_2017_v2.csv` (or reconcile the distributed metadata filename with the verifier), `train_val_list.txt`, `test_list.txt`, and `BBox_List_2017.csv`; the last file provides boxes for a limited pathology subset. The NIH Box page could not be checked anonymously in this environment, so its present download availability is **unconfirmed** here; do not assume an individual file URL will work without visiting the Box page.

NIH is **not interchangeable** with the guide's five CheXpert findings. Its labels, cohort, and localization subset differ; importantly, its box subset does not provide the same five-condition pixel masks as CheXlocalize. Choose one medical protocol and update the code, metrics, documentation and reported results consistently before interpreting cross-dataset comparisons.

## Before acquiring or using the data

### Server-side download helper

From a Linux server checkout of this repository, the operator can first probe the links, then download the available source archives to a chosen location:

```bash
bash scripts/download_datasets.sh --data-root /mnt/research-data --all --imagenet-direct --chexpert-direct --chexlocalize-api --probe
bash scripts/download_datasets.sh --data-root /mnt/research-data --all --imagenet-direct --chexpert-direct --chexlocalize-api
```

`--imagenet-direct` bypasses the need to install the Kaggle CLI **on the server**, using publisher-hosted ImageNet files. `--chexpert-direct` uses the full publisher-hosted CheXpert ZIP. Both flags still assume the researcher has obtained the applicable authorization and agreed to publisher terms; they do not remove access obligations. `--chexlocalize-api` uses the **separate** authorized Redivis REST API; `--all` by itself does not silently use your token. The second command above initiates approximately **620 GB of ImageNet and CheXpert compressed files alone**, plus ~3.9 GB of Redivis files, before CUB/VOC, other masks, extraction, and working space; run it only after confirming access rights and ample capacity.

To test or fetch **only** the official CheXlocalize Redivis files, without touching the much larger archives:

```bash
bash scripts/download_datasets.sh --data-root /mnt/research-data --chexlocalize-api --probe
bash scripts/download_datasets.sh --data-root /mnt/research-data --chexlocalize-api
```

The second command saves the Redivis files under `/mnt/research-data/_archives/chexlocalize/CheXlocalize/`, preserving their indexed paths. It resumes `.part` transfers and compares every completed file with the index's size and MD5 digest. It does **not** get any CheXpert radiographs or label CSVs; the separate `--chexpert-direct` option is the expected source for training/validation files. Neither option extracts an archive or configures the current NIH-based medical code. Matching CheXpert **test** images/labels need a separate authorized source if test localization is in scope.

`--probe` (also accepted as `--dry-run` for older commands) **does use the network**: it requests only the first 4 KiB of each selected direct archive, requiring a partial-content response. With `--chexlocalize-api`, it also reads Redivis's small table metadata and one file-index row, then requests just 4 KiB of one ground-truth JSON file and discards it. Without `--imagenet-direct`, it instead downloads Kaggle's small `LOC_synset_mapping.txt` to `_archives/_probe/imagenet/` and requires Kaggle authentication. It will not silently fetch a whole archive if a host ignores byte ranges; that result is reported as *unverified*. A passing probe proves limited access at that moment, **not** that the whole file is intact, enough disk space exists, or future transfers will work. NIH is not probed. The probe requires `curl` 8.4 or newer so its transfer-size cap is enforced even when a server omits file size.

On 29 September 2026, the updated script received HTTP 206 and exactly 4,096 bytes from all five publisher-hosted ImageNet archives, the full Stanford-hosted CheXpert ZIP, the ImageNet-S-50 annotation archive, and an authenticated CheXlocalize ground-truth JSON file. Earlier bounded probes also passed for both CUB archives and the VOC archive. The full Redivis index was read as metadata and validated to contain 2,349 unique paths with sizes and MD5 digests. This confirms limited access and manifest structure, **not** a full transfer or byte-for-byte integrity of the CheXlocalize files. Kaggle was **not** probed successfully here because the CLI was not installed/authenticated; NIH remains unverified.

The full-download mode places files in `/mnt/research-data/_archives/{imagenet,imagenet_s50,cub200,voc,chexpert,chexlocalize}/` and prints the Stanford access steps. Use `--cub`, `--voc`, or `--imagenet` to fetch one family; add `--sbd` only with `--voc` or `--all` for the optional augmented VOC protocol. `--nih` prints the separate NIH path used by the unchanged code. The server needs `curl`, `tar`, `unzip`, `md5sum`, and Python 3 for `--chexlocalize-api`. The [official Kaggle CLI](https://github.com/Kaggle/kaggle-cli/blob/main/docs/competitions.md) is needed only for the default ImageNet route, not `--imagenet-direct`. The script checks full archive integrity, checks published MD5 sums where available, and keeps interrupted transfers as `.part` files. For the Kaggle route, the server operator must authenticate and accept the ImageNet competition rules using their **own authorized account**.

On **Windows without WSL**, open **Git Bash** (included with [Git for Windows](https://gitforwindows.org/)), navigate to this repository, and use Git Bash paths (`/c/...` for drive C:, `/d/...` for drive D:). For example:

```bash
cd /c/Users/Jayan/Coding/Projects/Research/vit-explainability-benchmark
bash scripts/download_datasets.sh --data-root /d/research-data --all --imagenet-direct --chexpert-direct --chexlocalize-api --probe
```

Replace `/d/research-data` with a real drive and folder that has sufficient space. `/mnt/...` is a WSL/Linux path, not a native Git Bash destination. For the remote Linux server, clone the repository there and use that server's own absolute data path. Kaggle authentication is needed only when using the Kaggle route.

**This is a download helper, not dataset preparation.** It deliberately does not extract archives, create the loader-specific directory layout, filter the five medical labels, or repair the repository's current NIH/CheXpert mismatch. CheXpert can be transferred by its direct option if your access is authorized; CheXlocalize annotations/maps can be transferred with the authorized Redivis option; NIH still needs its separate access path. Validation images/labels should come from CheXpert, but test images/labels remain a separate acquisition if using CheXlocalize test annotations. If Stanford supplies a temporary Azure Blob SAS URL for the older combined CheXlocalize/CheXpert package, [AzCopy supports a recursive container transfer](https://learn.microsoft.com/en-us/azure/storage/common/storage-use-azcopy-blobs-download), but the SAS is a bearer credential: on a shared server, obtain the owner's permission and keep it out of scripts, terminal history, process listings where practical, logs, and version control. It expires and cannot be treated as a permanent public link.

### TODO: validate prepared datasets after download and extraction

This check is **not implemented yet**. The downloader's archive tests, publisher checksums, Redivis file-size/MD5 comparisons, and 4 KiB link probes only check transfers; they do not prove that the extracted data is complete or that different sources line up correctly. Extend [`scripts/verify_datasets.py`](../scripts/verify_datasets.py), which currently covers CUB, VOC, ImageNet-S and NIH but **not CheXpert/CheXlocalize**, and run it before training or reporting results. The future check should:

- Confirm the expected extracted files, image counts and split manifests for each selected dataset, and compare publisher checksums or indexed digests where available.
- For the medical subset, require CheXpert training/validation images and label CSVs; parse the selected five columns; verify that every evaluation image ID and finding used from CheXlocalize has a matching image, label and decoded human mask/point.
- Fail clearly if test localization is requested but authorized matching test X-rays/labels are absent; check patient-level split separation and report unmatched or duplicate IDs.

Until this TODO is implemented and passes on the prepared data, a successful download or probe must **not** be reported as a validated benchmark dataset.

- Accept each publisher's terms. Do not commit images, credentials, signed download links or patient data to this repository.
- Keep the complete publisher archives/records and record their versions, checksums where provided, and exact train/validation/test IDs. Do not infer an evaluation split from file order.
- Classification labels tell **what** is present; boxes, part points and segmentation masks tell **where**. Use only examples with the relevant spatial annotation when computing localization metrics.
- The public archive links above have only been probed with small byte ranges, **not** by transferring complete archives. Account-gated payloads and full transfers must be confirmed after authorized access.
